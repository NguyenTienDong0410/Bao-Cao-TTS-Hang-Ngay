## I. Kiến Trúc Cơ Bản của Database Server

### 1.1. Mô hình Client-Server trong hệ thống Database

Mô hình client-server là kiến trúc nền tảng được sử dụng rộng rãi trong các hệ thống cơ sở dữ liệu hiện đại. Trong mô hình này, hệ thống được phân chia thành hai thành phần chính:

**Client (Máy khách):** Là phía gửi yêu cầu truy vấn dữ liệu. Client có thể là ứng dụng web, ứng dụng di động, công cụ quản trị CSDL (như DBeaver, MySQL Workbench), hoặc một dịch vụ backend khác. Client không lưu trữ hay xử lý dữ liệu trực tiếp mà chỉ thực hiện các yêu cầu thông qua giao thức kết nối.

**Server (Máy chủ):** Là phía tiếp nhận, xử lý yêu cầu và trả về kết quả cho client. Database server chịu trách nhiệm quản lý toàn bộ dữ liệu, kiểm soát truy cập, xử lý truy vấn và đảm bảo tính toàn vẹn của dữ liệu.

Luồng hoạt động cơ bản diễn ra theo trình tự sau:

```
Client  →  [Gửi yêu cầu / SQL Query]  →  Database Server
        ←  [Trả kết quả / Result Set]  ←
```

Giao tiếp giữa client và server diễn ra thông qua các giao thức mạng như TCP/IP. Mỗi DBMS sử dụng cổng mặc định riêng: MySQL dùng cổng 3306, PostgreSQL dùng 5432, MSSQL dùng 1433, MongoDB dùng 27017, Redis dùng 6379.

Ưu điểm nổi bật của mô hình này là khả năng phục vụ nhiều client đồng thời, tập trung hóa việc quản lý dữ liệu, dễ dàng sao lưu và bảo mật, đồng thời cho phép mở rộng quy mô một cách linh hoạt.

### 1.2. Các thành phần cơ bản của Database Server

Một database server hoàn chỉnh bao gồm các thành phần cốt lõi sau:

**Query Processor (Bộ xử lý truy vấn)**
Đây là thành phần tiếp nhận câu lệnh SQL/NoSQL từ client, phân tích cú pháp (parsing), kiểm tra tính hợp lệ, sau đó tối ưu hóa và sinh ra kế hoạch thực thi (execution plan). Trình tối ưu hóa truy vấn (Query Optimizer) đóng vai trò quan trọng trong việc lựa chọn phương án thực thi hiệu quả nhất.

**Storage Engine (Bộ máy lưu trữ)**
Là tầng chịu trách nhiệm đọc và ghi dữ liệu lên đĩa cứng. Mỗi DBMS có thể hỗ trợ nhiều storage engine khác nhau. Ví dụ, MySQL hỗ trợ InnoDB (mặc định, hỗ trợ transaction và khóa ngoại) và MyISAM (tốc độ đọc nhanh nhưng không hỗ trợ transaction). Storage engine quyết định cách dữ liệu được tổ chức trên đĩa, cấu trúc chỉ mục và cơ chế phục hồi dữ liệu.

**Buffer Pool / Cache Manager (Bộ quản lý bộ nhớ đệm)**
Để tránh phải đọc dữ liệu từ đĩa cứng mỗi lần (vốn rất chậm), database server duy trì một vùng bộ nhớ RAM gọi là buffer pool. Dữ liệu được tải lên RAM khi truy cập và giữ lại để phục vụ các yêu cầu tiếp theo. Đây là yếu tố then chốt ảnh hưởng đến hiệu năng tổng thể.

**Transaction Manager (Bộ quản lý giao dịch)**
Đảm bảo các giao dịch tuân thủ các thuộc tính ACID (Atomicity, Consistency, Isolation, Durability). Transaction Manager điều phối việc thực thi giao dịch, quản lý khóa (locking) và xử lý các tình huống deadlock.

**Lock Manager (Bộ quản lý khóa)**
Kiểm soát việc truy cập đồng thời vào cùng một tài nguyên dữ liệu. Sử dụng các cơ chế khóa khác nhau (shared lock, exclusive lock, row-level lock, table-level lock) để đảm bảo tính nhất quán khi nhiều người dùng cùng thao tác.

**Log Manager (Bộ quản lý nhật ký)**
Ghi lại toàn bộ các thay đổi trên dữ liệu vào Write-Ahead Log (WAL) trước khi thực sự áp dụng lên dữ liệu. Đây là cơ chế quan trọng để phục hồi dữ liệu khi có sự cố (crash recovery).

**Connection Manager (Bộ quản lý kết nối)**
Tiếp nhận và quản lý các kết nối từ client, phân bổ tài nguyên cho từng phiên làm việc (session), xác thực người dùng và kiểm soát số lượng kết nối đồng thời.

### 1.3. Sự khác biệt giữa Database và Database Server

Hai khái niệm này thường bị nhầm lẫn trong thực tế. Bảng dưới đây làm rõ sự khác biệt:

| Tiêu chí | Database (Cơ sở dữ liệu) | Database Server (Máy chủ CSDL) |
|---|---|---|
| Định nghĩa | Tập hợp dữ liệu có cấu trúc được lưu trữ có tổ chức | Phần mềm / hệ thống quản lý và cung cấp truy cập vào database |
| Bản chất | Là dữ liệu (data) | Là phần mềm (software) hoặc máy chủ vật lý |
| Ví dụ | File `.mdf` trong SQL Server, thư mục data trong MySQL | MySQL, PostgreSQL, SQL Server, Oracle |
| Vai trò | Lưu trữ thông tin | Xử lý truy vấn, quản lý bảo mật, kiểm soát truy cập |
| Tồn tại độc lập | Không hoạt động mà không có DBMS | Có thể chứa nhiều database khác nhau |
| Tương tự thực tế | Cuốn sách trong thư viện | Toàn bộ hệ thống thư viện và nhân viên quản lý |

Nói một cách đơn giản: **Database** là kho chứa dữ liệu, còn **Database Server** là hệ thống phần mềm quản lý kho đó, cung cấp giao diện để người dùng có thể truy vấn, thêm, sửa, xóa dữ liệu một cách an toàn và hiệu quả.

### 1.4. Các loại Database Server phổ biến

#### RDBMS (Relational Database Management System)

RDBMS là hệ quản trị cơ sở dữ liệu quan hệ, tổ chức dữ liệu theo mô hình bảng (table) với các hàng (row) và cột (column). Các bảng liên kết với nhau thông qua khóa ngoại (foreign key). Hệ thống sử dụng ngôn ngữ SQL làm ngôn ngữ truy vấn chuẩn và đảm bảo đầy đủ các thuộc tính ACID.

Đại diện tiêu biểu: MySQL, PostgreSQL, Microsoft SQL Server, Oracle Database, MariaDB.

Phù hợp với: hệ thống tài chính, ngân hàng, ERP, CRM — các ứng dụng yêu cầu tính nhất quán dữ liệu cao.

#### NoSQL (Not Only SQL)

NoSQL ra đời để giải quyết những giới hạn của RDBMS truyền thống trong bối cảnh dữ liệu lớn và phân tán. NoSQL không sử dụng mô hình bảng quan hệ mà thay vào đó hỗ trợ nhiều mô hình lưu trữ linh hoạt hơn.

Các mô hình NoSQL phổ biến:

- **Document Store:** Lưu dữ liệu dạng tài liệu JSON/BSON. Đại diện: MongoDB, CouchDB.
- **Key-Value Store:** Lưu dữ liệu theo cặp key-value. Đại diện: Redis, DynamoDB, Memcached.
- **Column-Family Store:** Tổ chức dữ liệu theo cột thay vì hàng. Đại diện: Apache Cassandra, HBase.
- **Graph Database:** Tập trung vào mối quan hệ giữa các đối tượng. Đại diện: Neo4j, Amazon Neptune.

Phù hợp với: ứng dụng web quy mô lớn, mạng xã hội, IoT, real-time analytics, nơi yêu cầu khả năng mở rộng theo chiều ngang (horizontal scaling) và độ trễ thấp.

#### NewSQL

NewSQL là thế hệ DBMS mới, được thiết kế nhằm kết hợp ưu điểm của cả RDBMS (đảm bảo ACID, hỗ trợ SQL đầy đủ) và NoSQL (khả năng mở rộng ngang, hiệu năng cao với dữ liệu lớn). NewSQL thích hợp cho các ứng dụng cần xử lý hàng triệu giao dịch mỗi giây mà vẫn đảm bảo tính nhất quán.

Đại diện tiêu biểu: Google Spanner, CockroachDB, TiDB, VoltDB, NuoDB.

## II. Hệ Quản Trị Cơ Sở Dữ Liệu (DBMS)

### 2.1. MySQL / MariaDB

**MySQL** là hệ quản trị cơ sở dữ liệu quan hệ mã nguồn mở phổ biến nhất thế giới, được Oracle Corporation phát triển và duy trì. MySQL ra đời năm 1995 và hiện là lựa chọn hàng đầu cho các ứng dụng web.

**MariaDB** là nhánh (fork) của MySQL được tạo ra năm 2009 bởi chính những người sáng lập MySQL sau khi Oracle mua lại Sun Microsystems. MariaDB duy trì khả năng tương thích cao với MySQL nhưng bổ sung nhiều tính năng mới và cải tiến hiệu năng.

**Đặc điểm kỹ thuật:**
- Hỗ trợ nhiều storage engine: InnoDB (mặc định), MyISAM, Aria, RocksDB (MariaDB)
- Sử dụng cổng mặc định 3306
- Hỗ trợ replication Master-Slave và Master-Master
- Tích hợp tốt với ngăn xếp LAMP (Linux, Apache, MySQL, PHP)
- Hỗ trợ stored procedures, triggers, views, và full-text search

**Trường hợp sử dụng:** Website thương mại điện tử, blog (WordPress), CMS (Drupal, Joomla), ứng dụng SaaS quy mô vừa.

---

### 2.2. Microsoft SQL Server

Microsoft SQL Server (MSSQL) là hệ quản trị cơ sở dữ liệu quan hệ được Microsoft phát triển, ra mắt lần đầu năm 1989. Đây là một trong những DBMS thương mại hàng đầu, đặc biệt phổ biến trong môi trường doanh nghiệp sử dụng hệ sinh thái Microsoft.

**Đặc điểm kỹ thuật:**
- Ngôn ngữ truy vấn mở rộng: T-SQL (Transact-SQL) với nhiều tính năng hơn SQL chuẩn
- Sử dụng cổng mặc định 1433
- Tích hợp chặt chẽ với Windows Active Directory và Azure
- Hỗ trợ SQL Server Integration Services (SSIS), Reporting Services (SSRS), Analysis Services (SSAS)
- Có các phiên bản: Express (miễn phí, giới hạn), Standard, Enterprise, Developer
- Từ phiên bản 2017 trở đi hỗ trợ cài đặt trên Linux và Docker
- Tính năng Always On Availability Groups cho High Availability

**Trường hợp sử dụng:** Hệ thống ERP, CRM doanh nghiệp, ứng dụng .NET, hệ thống tài chính - kế toán, Business Intelligence.

---

### 2.3. Oracle Database

Oracle Database là hệ quản trị cơ sở dữ liệu thương mại mạnh mẽ nhất thị trường, được Oracle Corporation phát triển từ năm 1979. Oracle là lựa chọn hàng đầu cho các hệ thống doanh nghiệp lớn, yêu cầu độ tin cậy và hiệu năng cao nhất.

**Đặc điểm kỹ thuật:**
- Hỗ trợ ngôn ngữ PL/SQL mạnh mẽ với các tính năng lập trình nâng cao
- Sử dụng cổng mặc định 1521
- Kiến trúc đa người dùng (multi-tenant) với Container Database (CDB) và Pluggable Database (PDB)
- Hỗ trợ Real Application Clusters (RAC) cho khả năng mở rộng và HA
- Tính năng Automatic Storage Management (ASM)
- Tích hợp sẵn Data Guard cho disaster recovery
- Hỗ trợ In-Memory Database và JSON/XML natively

**Trường hợp sử dụng:** Ngân hàng, viễn thông, chính phủ, hệ thống lõi doanh nghiệp (core banking, ERP SAP), các ứng dụng yêu cầu SLA cực cao.

---

### 2.4. PostgreSQL

PostgreSQL (thường gọi là "Postgres") là hệ quản trị cơ sở dữ liệu quan hệ đối tượng (Object-Relational) mã nguồn mở, được phát triển từ dự án POSTGRES tại UC Berkeley năm 1986. PostgreSQL nổi tiếng với sự tuân thủ chuẩn SQL nghiêm ngặt và tập tính năng phong phú.

**Đặc điểm kỹ thuật:**
- Hỗ trợ đầy đủ ACID và MVCC (Multi-Version Concurrency Control)
- Sử dụng cổng mặc định 5432
- Hỗ trợ kiểu dữ liệu phong phú: JSON, JSONB, XML, Array, Hstore, Geometric types
- Hỗ trợ Full-Text Search tích hợp sẵn
- Hỗ trợ extensions mạnh mẽ: PostGIS (địa lý), TimescaleDB (time-series), pgvector (AI vector search)
- Hệ thống phân quyền chi tiết theo cột (column-level security)
- Logical Replication và Streaming Replication

**Trường hợp sử dụng:** Ứng dụng GIS, hệ thống phân tích dữ liệu, ứng dụng yêu cầu tuân thủ SQL chuẩn cao, fintech, startup cần cơ sở dữ liệu linh hoạt và mạnh mẽ.

---

### 2.5. MongoDB (NoSQL)

MongoDB là hệ quản trị cơ sở dữ liệu NoSQL dạng document store phổ biến nhất thế giới, được MongoDB Inc. phát triển và ra mắt năm 2009. MongoDB lưu trữ dữ liệu dưới dạng tài liệu BSON (Binary JSON), cho phép cấu trúc dữ liệu linh hoạt.

**Đặc điểm kỹ thuật:**
- Dữ liệu lưu theo dạng collections (tương đương tables) chứa documents (tương đương rows)
- Sử dụng cổng mặc định 27017
- Schema linh hoạt — mỗi document trong cùng collection có thể có cấu trúc khác nhau
- Hỗ trợ Aggregation Pipeline mạnh mẽ cho phân tích dữ liệu
- Native horizontal scaling qua Sharding
- Replica Set cho High Availability
- Hỗ trợ ACID transactions từ phiên bản 4.0 (multi-document)
- Hỗ trợ Atlas Search (full-text search) và Atlas Vector Search

**Trường hợp sử dụng:** Ứng dụng catalog sản phẩm, quản lý nội dung (CMS), IoT data, user profiles, real-time analytics, ứng dụng có cấu trúc dữ liệu thay đổi thường xuyên.

---

### 2.6. Redis

Redis (Remote Dictionary Server) là hệ thống lưu trữ cấu trúc dữ liệu in-memory mã nguồn mở, ra đời năm 2009 bởi Salvatore Sanfilippo. Redis thường được sử dụng làm cache, message broker, và cơ sở dữ liệu tốc độ cao.

**Đặc điểm kỹ thuật:**
- Toàn bộ dữ liệu lưu trên RAM → độ trễ cực thấp (dưới 1 millisecond)
- Sử dụng cổng mặc định 6379
- Hỗ trợ nhiều kiểu dữ liệu: String, Hash, List, Set, Sorted Set, Bitmap, HyperLogLog, Streams, Geospatial
- Hỗ trợ persistence qua RDB (snapshots) và AOF (Append Only File)
- Pub/Sub messaging
- Lua scripting
- Redis Cluster cho horizontal scaling
- Redis Sentinel cho High Availability
- Redis Stack bổ sung: RedisJSON, RediSearch, RedisTimeSeries, RedisGraph

**Trường hợp sử dụng:** Session caching, rate limiting, leaderboard/ranking, real-time pub/sub messaging, queue management, distributed locking.

| **MongoDB** | Schema linh hoạt, dễ scale ngang, phù hợp dữ liệu phi cấu trúc, JSON native, dễ học cho developer | Không đảm bảo toàn vẹn dữ liệu như RDBMS, tốn RAM, join phức tạp và kém hiệu quả |
| **Redis** | Tốc độ cực nhanh (in-memory), hỗ trợ nhiều cấu trúc dữ liệu, pub/sub tích hợp | Dữ liệu bị mất khi mất điện nếu không cấu hình persistence, chi phí RAM cao |

### 2.8. Tiêu chí lựa chọn DBMS phù hợp

Việc lựa chọn DBMS cần dựa trên nhiều yếu tố:

**Tính chất dữ liệu:** Nếu dữ liệu có cấu trúc rõ ràng, quan hệ chặt chẽ → RDBMS. Nếu dữ liệu phi cấu trúc, thay đổi linh hoạt → NoSQL.

**Yêu cầu tính nhất quán:** Ứng dụng tài chính, ngân hàng → cần ACID đầy đủ → RDBMS. Ứng dụng mạng xã hội, IoT → BASE (Basically Available, Soft state, Eventually consistent) có thể chấp nhận → NoSQL.

**Quy mô và khả năng mở rộng:** Nếu cần scale ngang hàng trăm node → NoSQL (MongoDB, Cassandra). Nếu quy mô vừa phải và ưu tiên nhất quán → RDBMS với replication.

**Ngân sách:** MySQL, PostgreSQL, MongoDB Community Edition miễn phí. Oracle, MSSQL Enterprise tốn kém đáng kể.

**Kỹ năng đội ngũ:** Đội ngũ quen với SQL → RDBMS. Đội ngũ .NET → MSSQL. Startup web → MySQL/PostgreSQL/MongoDB.

**Yêu cầu hiệu năng:** Cần cache tốc độ cao → Redis. Cần xử lý OLAP → PostgreSQL hoặc giải pháp columnar storage.

**Hệ sinh thái và tích hợp:** Ứng dụng Microsoft → MSSQL. Ứng dụng AWS → Aurora (MySQL/PostgreSQL compatible). Ứng dụng Google → Cloud Spanner.

## III. Cài Đặt và Cấu Hình

### 3.1. Yêu cầu hệ thống phần cứng

Yêu cầu phần cứng phụ thuộc vào quy mô triển khai, loại workload và lượng dữ liệu. Dưới đây là mức khuyến nghị cho môi trường development và production nhỏ:

| Thành phần | MySQL/MariaDB | MSSQL | MongoDB | Redis |
|---|---|---|---|---|
| **CPU** | 2+ cores | 4+ cores | 2+ cores | 1+ core |
| **RAM (Dev)** | 1 GB | 2 GB | 1 GB | 512 MB |
| **RAM (Prod)** | 8–32 GB | 16–64 GB | 8–32 GB | Bằng dataset |
| **Disk (Dev)** | 10 GB | 20 GB | 10 GB | 2 GB |
| **Disk (Prod)** | SSD, 100 GB+ | SSD, 100 GB+ | SSD, 100 GB+ | SSD (nếu persist) |
| **Network** | 1 Gbps | 1 Gbps | 1 Gbps | 1 Gbps |
| **OS** | Linux/Windows | Windows/Linux | Linux/Windows | Linux |

**Lưu ý quan trọng về phần cứng:**
- Ưu tiên **RAM lớn** cho tất cả DBMS vì buffer pool/cache quyết định phần lớn hiệu năng.
- Sử dụng **SSD NVMe** thay vì HDD để giảm I/O latency đáng kể.
- Với Redis, toàn bộ dataset phải vừa trong RAM, vì vậy cần tính toán kỹ dung lượng.
- Tách riêng đĩa lưu data và đĩa lưu log để tránh tranh chấp I/O.

```ini
[mysqld]

# Đặt khoảng 70-80% RAM hệ thống

# Số lượng buffer pool instances (tăng song song)

# ===== InnoDB Log =====
# Tăng log file để giảm checkpoint frequency
innodb_log_file_size = 1G
innodb_log_buffer_size = 64M

# ===== Connections =====
max_connections = 500
thread_cache_size = 50

# ===== Query Cache (MySQL 5.7 trở về trước) =====
query_cache_type = 0
query_cache_size = 0

# ===== Temporary Tables =====
tmp_table_size = 256M
max_heap_table_size = 256M

# ===== Slow Query Log =====
slow_query_log = 1
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 2

# ===== Binary Log (cho Replication) =====
server_id = 1
log_bin = /var/log/mysql/mysql-bin.log
binlog_expire_logs_seconds = 604800  # 7 ngày
sync_binlog = 1

# ===== I/O =====
innodb_flush_method = O_DIRECT
innodb_flush_log_at_trx_commit = 1
```

#### Cấu hình bảo mật cơ bản

```sql
-- Đăng nhập với quyền root

-- Tạo user mới chỉ cho phép từ localhost

-- Tạo user cho phép từ subnet cụ thể

-- Áp dụng thay đổi quyền

-- Xóa user ẩn danh nếu còn tồn tại
DELETE FROM mysql.user WHERE User='';
FLUSH PRIVILEGES;

-- Đổi mật khẩu root
ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewStrongPassword@789';
```

### 3.3. Microsoft SQL Server (MSSQL)

#### Cài đặt trên Windows Server

Tải SQL Server Installer từ trang chính thức của Microsoft. Quá trình cài đặt qua giao diện đồ họa:

1. Chạy `setup.exe` với quyền Administrator
2. Chọn loại cài đặt: **New SQL Server stand-alone installation**
3. Chọn Edition: Developer (miễn phí cho dev), Express (miễn phí, giới hạn 10GB), hoặc nhập Product Key cho Standard/Enterprise
4. Chấp nhận License Terms

6. Cấu hình Instance: Default Instance (`MSSQLSERVER`) hoặc Named Instance
7. Cấu hình Service Accounts và Collation
8. Chọn Authentication Mode: **Mixed Mode** (SQL Server + Windows Authentication) và đặt mật khẩu SA
9. Hoàn tất cài đặt

```bash
# Import Microsoft GPG key
```

#### Cấu hình tối ưu hiệu năng

File cấu hình chính: `/etc/mongod.conf`

```yaml
# Cấu hình lưu trữ
storage:
  dbPath: /var/lib/mongodb
  journal:
    enabled: true
  engine: wiredTiger
  wiredTiger:
    engineConfig:
      # Cache size = khoảng 50% RAM hệ thống (mặc định là 50% RAM - 1GB)
      cacheSizeGB: 8
      journalCompressor: snappy
    collectionConfig:
      blockCompressor: snappy
    indexConfig:
      prefixCompression: true

# Cấu hình log
systemLog:
  destination: file
  logAppend: true
  path: /var/log/mongodb/mongod.log
  verbosity: 0

# Cấu hình mạng
net:
  port: 27017
  bindIp: 127.0.0.1  # Chỉ lắng nghe localhost (bảo mật)
  # Để cho phép kết nối từ xa: bindIp: 0.0.0.0

# Cấu hình tiến trình
processManagement:
  timeZoneInfo: /usr/share/zoneinfo

# Cấu hình bảo mật
security:
  authorization: enabled  # Bật xác thực

# Cấu hình replication (nếu dùng Replica Set)
replication:
  replSetName: "rs0"

# Giới hạn connection
net:
  maxIncomingConnections: 1000
```

Cấu hình hệ điều hành để tối ưu MongoDB:

```bash
# Tắt Transparent Huge Pages (THP) - MongoDB khuyến nghị tắt
echo 'never' | sudo tee /sys/kernel/mm/transparent_hugepage/enabled
echo 'never' | sudo tee /sys/kernel/mm/transparent_hugepage/defrag

# Tăng giới hạn file mô tả
echo "mongod soft nofile 64000" | sudo tee -a /etc/security/limits.conf
echo "mongod hard nofile 64000" | sudo tee -a /etc/security/limits.conf

# Cấu hình vm.swappiness
echo "vm.swappiness = 1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

```bash
# Khởi động dịch vụ
sudo systemctl start redis-server
sudo systemctl enable redis-server

redis-cli ping
# Kết quả mong đợi: PONG
```

#### Cấu hình tối ưu hiệu năng

File cấu hình chính: `/etc/redis/redis.conf`

```bash
# ===== Mạng =====
bind 127.0.0.1          # Chỉ lắng nghe localhost (bảo mật)
port 6379
protected-mode yes

# ===== Bộ nhớ =====
# Giới hạn tổng RAM Redis được phép sử dụng
maxmemory 4gb

# Chính sách eviction khi đầy memory
# allkeys-lru: xóa key ít dùng nhất (phù hợp cache thuần)
# volatile-lru: chỉ xóa key có TTL, dùng LRU
# noeviction: trả lỗi khi đầy (phù hợp lưu trữ lâu dài)
maxmemory-policy allkeys-lru

# ===== Persistence =====
# RDB Snapshots
save 900 1       # Lưu nếu có ít nhất 1 thay đổi trong 900 giây
save 300 10      # Lưu nếu có ít nhất 10 thay đổi trong 300 giây
save 60 10000    # Lưu nếu có ít nhất 10000 thay đổi trong 60 giây

# Tên file RDB
dbfilename dump.rdb
dir /var/lib/redis

# AOF (Append Only File) - an toàn hơn RDB
appendonly yes
appendfilename "appendonly.aof"
appendfsync everysec    # everysec: cân bằng giữa an toàn và hiệu năng
                        # always: an toàn nhất nhưng chậm nhất
                        # no: nhanh nhất nhưng có thể mất dữ liệu

# ===== Lazy Deletion =====
lazyfree-lazy-eviction yes
lazyfree-lazy-expire yes
lazyfree-lazy-server-del yes

# ===== Số lượng databases =====
databases 16

# ===== Connection =====
maxclients 10000
timeout 300          # Đóng kết nối idle sau 300 giây

# ===== Log =====
loglevel notice
logfile /var/log/redis/redis-server.log
```

Cấu hình hệ điều hành cho Redis:

```bash
# Tắt THP (bắt buộc để tránh latency spikes)
echo never | sudo tee /sys/kernel/mm/transparent_hugepage/enabled

# Tắt overcommit memory (Redis yêu cầu khi dùng persistence)
echo "vm.overcommit_memory = 1" | sudo tee -a /etc/sysctl.conf
sudo sysctl vm.overcommit_memory=1

# Tăng backlog kết nối
echo "net.core.somaxconn = 65535" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

#### Cấu hình bảo mật cơ bản

```bash

# 3. Giới hạn bindIp
```
