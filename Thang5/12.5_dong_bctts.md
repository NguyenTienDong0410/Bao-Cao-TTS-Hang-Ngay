## 5. Cài đặt và cấu hình FTP Server

### 5.1. Yêu cầu hệ thống

Việc thiết lập một FTP Server không đòi hỏi tài nguyên phần cứng quá lớn, nhưng cần đảm bảo tính ổn định và bảo mật để phục vụ được nhiều kết nối đồng thời.

**Yêu cầu phần cứng (khuyến nghị cơ bản):**

- **CPU:** 1 GHz trở lên, khuyến nghị từ 2 nhân để xử lý nhiều kết nối đồng thời.
- **RAM:** Tối thiểu 512 MB; khuyến nghị 2 GB trở lên nếu có nhiều người dùng.
- **Ổ cứng (Storage):** Dung lượng tùy thuộc vào lượng dữ liệu cần lưu trữ. Nên sử dụng ổ SSD để tăng tốc độ đọc/ghi.
- **Mạng (Network):** Đường truyền ổn định. Đặc biệt cần có **IP tĩnh (Static IP)** nếu muốn truy cập từ xa qua Internet.

**Hệ điều hành được hỗ trợ:**

- **Windows:** Windows 10/11, Windows Server 2016/2019/2022 — giao diện trực quan, dễ sử dụng.
- **Linux:** Ubuntu, CentOS, Debian, RedHat — được khuyến nghị vì tính ổn định cao, bảo mật tốt và tiêu tốn ít tài nguyên.
- **macOS:** macOS Catalina trở lên.

### 5.2. Hướng dẫn cài đặt theo từng hệ điều hành

#### A. Trên Windows — Sử dụng FileZilla Server

FileZilla Server là phần mềm mã nguồn mở, miễn phí và rất phổ biến trên nền tảng Windows.

1. Truy cập trang chủ FileZilla ([https://filezilla-project.org](https://filezilla-project.org)) và tải về bản **FileZilla Server**.
2. Chạy file cài đặt `.exe`. Trong quá trình cài đặt, giữ nguyên các thiết lập mặc định (Standard).
3. Khi được yêu cầu, thiết lập **mật khẩu quản trị (Administration Password)**. Lưu ý: đây là mật khẩu để đăng nhập vào giao diện quản lý máy chủ, khác với mật khẩu tài khoản người dùng FTP.
4. Hoàn tất cài đặt và khởi động **FileZilla Server Administration Interface** để tiến hành cấu hình.

![Giao diện FileZilla Server Administration Interface](https://github.com/user-attachments/assets/590f87a1-aa8c-4e36-a39f-b7d43a0033e8)

---

#### B. Trên Linux — Sử dụng vsftpd trên Ubuntu/Debian

> Nội dung phần này đã được trình bày đầy đủ trong báo cáo ngày 11/05.

`vsftpd` (Very Secure FTP Daemon) là một trong những FTP server nhẹ và bảo mật nhất trên Linux.

1. Mở Terminal và cập nhật danh sách gói:

```bash
sudo apt update
```

2. Cài đặt vsftpd:

```bash
sudo apt install vsftpd
```

3. Kiểm tra trạng thái hoạt động của dịch vụ:

```bash
sudo systemctl status vsftpd
```

> Nhấn `q` để thoát màn hình trạng thái.

#### C. Trên macOS — Sử dụng tính năng có sẵn hoặc Homebrew

Cách nhanh nhất trên macOS là kích hoạt **SFTP** (giao thức bảo mật hơn FTP) thông qua tính năng có sẵn của hệ thống:

1. Vào **System Settings** (Tùy chọn Hệ thống) > **General** > **Sharing**.
2. Bật **Remote Login** (Đăng nhập Từ xa). Thao tác này sẽ kích hoạt SFTP server sử dụng cổng 22.
3. Nhấn biểu tượng `i` bên cạnh "Remote Login" để thêm các tài khoản người dùng được phép truy cập và cấu hình thư mục chia sẻ.

### 5.3. Cấu hình cơ bản: Tài khoản, thư mục và quyền truy cập

#### A. Đối với FileZilla Server (Windows)

1. Mở **FileZilla Server Administration Interface** và đăng nhập bằng mật khẩu quản trị đã thiết lập.
2. Vào menu **Server** > **Configure** > **Users**.
3. **Tạo tài khoản người dùng:** Nhấn `Add`, nhập tên đăng nhập (ví dụ: `nhanvien1`) và thiết lập mật khẩu bằng cách chọn **"Require password to log in"**.
4. **Cấu hình thư mục và phân quyền:**
   - Chuyển sang tab **Mount points** trong trang cài đặt của người dùng vừa tạo.
   - Nhấn `Add`. Tại cột **Virtual path**, nhập `/` (đây là thư mục gốc mà người dùng thấy khi đăng nhập).
   - Tại cột **Native path**, trỏ đến thư mục thực tế trên ổ cứng (ví dụ: `D:\FTP_Data`).
   - Phân quyền truy cập: Nhấp đúp vào mục quyền để cấp các quyền cần thiết, bao gồm Đọc (Read), Ghi (Write), Xóa (Delete) và Tạo thư mục (Create directories).

---

#### B. Đối với vsftpd (Linux)

1. **Tạo tài khoản người dùng hệ thống:**

```bash
sudo adduser ftpuser
```

Nhập mật khẩu và các thông tin theo yêu cầu.

2. **Chỉnh sửa file cấu hình:**

```bash
sudo nano /etc/vsftpd.conf
```

3. **Cấu hình các thông số cần thiết** (xóa dấu `#` ở đầu dòng nếu các dòng này đang bị chú thích):

```
anonymous_enable=NO      # Chặn đăng nhập ẩn danh
local_enable=YES         # Cho phép tài khoản người dùng cục bộ đăng nhập
write_enable=YES         # Cho phép ghi/upload file
chroot_local_user=YES    # Giới hạn người dùng trong thư mục Home, ngăn truy cập ra ngoài hệ thống
```

> Tùy chọn `chroot_local_user=YES` đặc biệt quan trọng về mặt bảo mật, vì nó ngăn người dùng điều hướng ra ngoài thư mục được cấp phép và xem các file hệ thống nhạy cảm.

![Cấu hình vsftpd.conf](https://github.com/user-attachments/assets/65db33f9-b2ae-46d8-9b4e-8a94f0d06955)

![Kết quả cấu hình](https://github.com/user-attachments/assets/85811148-c0ce-4127-8ce4-a5ec04348617)

4. **Lưu file và khởi động lại dịch vụ:**

Lưu file bằng `Ctrl+O`, xác nhận bằng `Enter`, thoát bằng `Ctrl+X`, sau đó khởi động lại:

```bash
sudo systemctl restart vsftpd
```

### 5.4. Tùy chỉnh nâng cao: Cổng, giới hạn băng thông và nhật ký hoạt động

#### 1. Tùy chỉnh cổng kết nối (Port Customization)

Mặc định, FTP sử dụng cổng **21**. Việc thay đổi sang cổng khác giúp giảm thiểu nguy cơ bị các công cụ quét cổng tự động phát hiện và tấn công.

- **FileZilla Server (Windows):** Vào **Settings** > **Server listeners**. Thay đổi `0.0.0.0:21` thành `0.0.0.0:2121` (hoặc cổng tùy chọn khác).
- **vsftpd (Linux):** Mở `/etc/vsftpd.conf`, thêm dòng:

```
listen_port=2121
```

Sau đó khởi động lại dịch vụ. Lưu ý: cổng mới cần được mở trên Firewall và Router tương ứng.

---

#### 2. Giới hạn băng thông (Bandwidth Limiting)

Giới hạn băng thông giúp ngăn một người dùng chiếm toàn bộ đường truyền mạng, đảm bảo chất lượng dịch vụ cho tất cả người dùng.

- **FileZilla Server (Windows):** Vào **Settings** > **Users** > Chọn người dùng > Tab **Speed limits**. Thiết lập giới hạn tốc độ tải xuống (Download) và tải lên (Upload) theo đơn vị kB/s.
- **vsftpd (Linux):** Mở `/etc/vsftpd.conf`, thêm dòng sau (đơn vị là Bytes/giây):

```
local_max_rate=1000000   # Giới hạn ở mức 1 MB/s
```

---

#### 3. Nhật ký hoạt động (Logging)

Nhật ký hoạt động là công cụ quan trọng để theo dõi và kiểm tra các hành vi bất thường trên máy chủ FTP.

- **FileZilla Server (Windows):** Vào **Settings** > **Logging**. Đánh dấu **"Enable logging to file"**. Có thể giới hạn kích thước file log để tránh đầy ổ cứng. File log thường được lưu tại `C:\Program Files\FileZilla Server\Logs`.
- **vsftpd (Linux):** Mở `/etc/vsftpd.conf`, đảm bảo dòng sau đã được bỏ dấu chú thích:

```
xferlog_enable=YES
```

Mặc định, log được lưu tại `/var/log/vsftpd.log`. Để xem lịch sử truy cập:

```bash
cat /var/log/vsftpd.log
```

## 6. Bảo mật FTP Server

### 6.1. Các rủi ro bảo mật phổ biến

#### Truyền dữ liệu không mã hóa

FTP truyền toàn bộ dữ liệu dưới dạng **plaintext** (văn bản thuần). Điều này có nghĩa là kẻ tấn công có thể sử dụng các công cụ như **Wireshark** để nghe lén (sniff) và đánh cắp tên đăng nhập, mật khẩu, cũng như nội dung file được truyền tải trên cùng một mạng.

#### Tấn công Brute Force

Kẻ tấn công có thể sử dụng công cụ tự động để thử liên tục hàng nghìn tổ hợp mật khẩu cho đến khi đăng nhập thành công. Do FTP mặc định không có cơ chế giới hạn số lần thử, đây là một trong những véctơ tấn công nguy hiểm nhất.

---

### 6.2. Giải pháp bảo vệ — FTPS và SFTP

Để khắc phục các rủi ro trên, cần chuyển sang sử dụng các giao thức có mã hóa thay vì FTP thuần túy.

#### FTPS (FTP over SSL/TLS)

FTPS là phần mở rộng của FTP, bổ sung lớp mã hóa SSL/TLS để bảo vệ dữ liệu trong quá trình truyền tải. Cấu hình vsftpd hỗ trợ FTPS:

```bash
ssl_enable=YES
rsa_cert_file=/etc/ssl/certs/vsftpd.pem
rsa_private_key_file=/etc/ssl/private/vsftpd.key
```

![Cấu hình FTPS trên vsftpd](https://github.com/user-attachments/assets/5167c98e-70aa-487b-ba83-e246763f0088)

#### SFTP (SSH File Transfer Protocol)

SFTP là giao thức truyền file hoạt động hoàn toàn qua kênh SSH, sử dụng cổng **22**. SFTP mã hóa toàn bộ phiên làm việc và được khuyến nghị ưu tiên sử dụng trong môi trường thực tế so với FTPS, vì không yêu cầu cấu hình chứng chỉ SSL riêng.

Kết nối SFTP từ client:

```bash
sftp user@server_ip
```

**Ví dụ thực hành — Tạo file trên máy chủ và tải về client:**

Tạo file `dong.txt` trên máy chủ:

![Tạo file dong.txt trên máy chủ](https://github.com/user-attachments/assets/20392706-404b-4c9f-9937-36bec7d68f60)

Tải file về bằng lệnh `get`:

```bash
get dong.txt
```

![Kết quả lệnh get dong.txt](https://github.com/user-attachments/assets/c5eb162a-a94f-43ca-9fd3-56cc2835b5fa)

File được tải về sẽ lưu tại thư mục mặc định của người dùng trên máy client, ví dụ: `C:\Users\admin\`

![File dong.txt sau khi tải về](https://github.com/user-attachments/assets/cfb41f1d-1628-426b-8f39-9f0b03511008)

---

#### Giới hạn IP truy cập

Hạn chế các địa chỉ IP được phép kết nối đến FTP Server là một lớp bảo vệ bổ sung hiệu quả, đặc biệt trong môi trường nội bộ doanh nghiệp.

Cấu hình tệp `/etc/hosts.allow` để chỉ cho phép dải mạng nội bộ:

```
# /etc/hosts.allow
vsftpd: 192.168.1.0/24
```

![Cấu hình hosts.allow](https://github.com/user-attachments/assets/7c4fa0ef-89b6-460c-9de8-a61b15e513b1)

Cấu hình tệp `/etc/hosts.deny` để chặn tất cả các IP còn lại:

```
# /etc/hosts.deny
vsftpd: ALL
```

### 6.3. Quản lý tài khoản người dùng

#### Chính sách mật khẩu mạnh

Sử dụng module PAM (`libpam-pwquality`) để bắt buộc tuân thủ chính sách mật khẩu:

```bash
sudo apt install libpam-pwquality
```

Cấu hình trong `/etc/security/pwquality.conf`:

```
minlen = 12        # Độ dài tối thiểu 12 ký tự
dcredit = -1       # Ít nhất 1 chữ số
ucredit = -1       # Ít nhất 1 chữ hoa
ocredit = -1       # Ít nhất 1 ký tự đặc biệt
```

#### Vô hiệu hóa truy cập ẩn danh

Đảm bảo tùy chọn `anonymous_enable` được đặt thành `NO` trong `/etc/vsftpd.conf`:

```
anonymous_enable=NO
local_enable=YES
```

![Cấu hình vô hiệu hóa anonymous access](https://github.com/user-attachments/assets/611812a6-e575-437b-85ab-4ccea6c80853)

Sau khi chỉnh sửa, khởi động lại dịch vụ để áp dụng thay đổi:

```bash
sudo systemctl restart vsftpd
```

## 7. Ứng dụng thực tế của FTP trong môi trường doanh nghiệp

Mặc dù ra đời từ rất lâu và hiện nay đã có các giao thức bảo mật hơn như SFTP và FTPS, FTP vẫn là một tiêu chuẩn cốt lõi trong ngành IT nhờ tính đơn giản, khả năng tương thích cao và hiệu quả truyền file lớn. Dưới đây là các ứng dụng thực tế phổ biến nhất trong môi trường doanh nghiệp và quản trị hệ thống.

### 7.1. Triển khai và quản trị Web Server

Đây là ứng dụng kinh điển nhất của FTP. Khi xây dựng một trang web chạy trên Nginx hoặc Apache, quản trị viên sử dụng FTP để đẩy source code (HTML, PHP, Python, hình ảnh...) từ máy tính cá nhân lên máy chủ thực tế. Các phần mềm như **FileZilla Client** cung cấp giao diện kéo thả trực quan, giúp Web Developer triển khai ứng dụng một cách nhanh chóng.

### 7.2. Tự động hóa sao lưu dữ liệu

Trong quản trị hệ thống, đảm bảo an toàn dữ liệu là ưu tiên hàng đầu. Quản trị viên thường viết các script (bằng Bash hoặc Python) để tự động nén dữ liệu website, cơ sở dữ liệu hoặc file log, sau đó sử dụng lệnh FTP để đẩy các bản backup này sang một máy chủ lưu trữ dự phòng riêng biệt theo lịch định kỳ (thường chạy vào đêm khuya để tránh ảnh hưởng đến hiệu năng hệ thống).

### 7.3. Cập nhật và lưu trữ cấu hình thiết bị mạng

Các thiết bị mạng như Switch, Router và Firewall thường không có giao diện lưu trữ đồ họa tiện lợi. Quản trị viên mạng sẽ thiết lập một **FTP Server** (hoặc **TFTP Server**) nội bộ để:

- Sao lưu file cấu hình (config) của thiết bị về máy tính quản lý.
- Đẩy các bản cập nhật Firmware lên thiết bị để tiến hành nâng cấp hệ điều hành của thiết bị.

### 7.4. Truyền tải file media dung lượng lớn

Khi cần truyền các file video thô dung lượng lớn hoặc hình ảnh chất lượng cao, giao thức HTTP của trình duyệt web thường gặp giới hạn về kích thước file hoặc bị timeout. FTP được thiết kế để xử lý file lớn, hỗ trợ truyền tải liên tục và có khả năng **resume** (tiếp tục truyền từ điểm bị gián đoạn) trong trường hợp mạng bị mất kết nối giữa chừng.

### 7.5. Trao đổi dữ liệu định kỳ giữa các hệ thống (B2B Integration)

Nhiều phần mềm doanh nghiệp như hệ thống kế toán, quản lý kho hoặc logistics không giao tiếp trực tiếp với nhau qua API. Thay vào đó, hệ thống A sẽ định kỳ xuất báo cáo dưới dạng file (CSV, XML...) và tự động đẩy lên FTP Server. Hệ thống B sẽ quét FTP Server theo lịch, tải file về và nạp vào cơ sở dữ liệu của mình. Đây là mô hình tích hợp phổ biến trong các doanh nghiệp chưa đầu tư vào hạ tầng API hiện đại.
